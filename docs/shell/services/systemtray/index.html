SystemTray Service

SystemTray.qml is N0ctOS's centralized StatusNotifier / system-tray service.

SystemTray.qml is N0ctOS's centralized StatusNotifier / system-tray service.

It gives every shell component one consistent place to list tray items, separate pinned from hidden icons, track attention state, trigger item actions, and open the single service-owned tray menu without touching Quickshell's native SystemTray model or configuration files directly.

The service supports native item adaptation, a pinned-is-not-hidden visibility model, hidden-id persistence, attention tracking, exact-id lookup, activation/secondary-activation/scroll/launch, one-at-a-time tray menus via the N0ctOS ContextMenu, and a full IPC interface.

4. Features / limitations

Features

Single entry point for tray state

All tray reads and actions go through:

instead of each panel, tooltip, or keybinding touching:

directly.

Adapter layer over native items

Quickshell's SystemTray.items is a live ObjectModel. Each native item receives exactly one N0ctOS adapter via a non-asynchronous Instantiator:

UI code binds to adapters, never to native items. The native object stays reachable as adapter._nativeItem for actions only.

Pinned-means-not-hidden model

There is no separate pinned list in config:

isPinned is defined as:

and isHidden is a membership test against _hiddenIds. pin()/show() remove the id; unpin()/hide() add it. togglePin() and toggleHidden() are the same storage with opposite polarity plus a find() existence check.

Hidden-id persistence

The service owns systemTray.hidden and nothing else in that section:

Unknown keys in systemTray are copied through on write, so other services can share the section without being clobbered.

syncFromConfig() runs on startup, on Config.onExternalReload, on Config.on_ConfigRevisionChanged (when ready), and on isReady transitions. It emits configurationChanged() and schedules a model sync only when the normalized list actually changed (JSON comparison).

Debounced model sync with a synchronous escape hatch

Native add/remove and config changes never rebuild models inline:

refresh IPC calls _syncModels() directly instead of scheduling. This is the refresh → _syncModels nuance: every other path is coalesced through Qt.callLater, while refresh rebuilds synchronously for tests and debugging.

_syncModels() walks the instantiator (objectAt(i)), partitions into pinned/hidden by isHidden, collects attention by isAttention, replaces all four arrays at once, and emits attentionChanged().

Attention tracking

Attention is derived, not stored:

_refreshAttention() recomputes from the current _items without rewalking the instantiator and is called on every native onStatusChanged. Full _syncModels() recomputes it as well.

Capability-gated actions

Every action checks its capability first:

Failures warn ([SystemTray] activate failed: etc.) and return false. Native calls are wrapped in try/catch so a misbehaving item cannot break the shell.

Launch prefers desktop entries

launch() tries an exact desktop-entry lookup first:

When the tray id does not correspond to a desktop entry, launch degrades to a normal activation instead of failing.

Single-menu backend states

Exactly one tray menu may be active. The backend cycles:

isMenuOpen is backend !== "none", so both pending and custom read as open. closeMenu() clears service state before calling ContextMenu.close() so the context menu's own close notification does not emit a second menuClosed. _clearMenuState() is the self-close path: it clears state without calling close() again.

The visible menu content is fully service-owned: native QsMenuEntry trees become ContextMenuObj rows (with checkbox/radio glyphs, separators, and recursive submenus), plus a trailing Hide/Show row for the active item. Developers never provide tray menu content.

Async DBus menu loading

DBus menus arrive over several round trips. Both the root menu and each submenu poll briefly:

Slow applications therefore fill in instead of staying empty. Lazily populated submenus that only send children after AboutToShow cannot load through QML (no invokable exposed by Quickshell) and stay empty by platform design.

Reactive configuration

_hiddenIds follows the config file without polling:

Adapter isHidden reads _hiddenIds live, so persisting a hide/show immediately re-partitions on the next sync.

JSON serialization for IPC

_snapshot() converts a live adapter into plain data (id, title, icon, tooltip parts, status, flags, capabilities, category). It intentionally omits the native object and live bindings so the result is JSON-safe for list / pinned / hidden / attention / get and for external scripts.

Limitations

No hidden-id validation against connected items

hidden[] may contain ids with no connected item. They are remembered (rememberedIds in the hidden IPC) and take effect if the application appears later. There is no garbage collection of stale ids.

togglePin() / toggleHidden() require a connected item

Direct pin() / unpin() / hide() / show() operate on raw ids and always persist. The toggle variants find() first:

Scripts that manage not-yet-running applications must use the non-toggle forms.

find() is an exact string match

There is no substring, case-insensitive, or category search. The id is String(native.id || ""), so empty-id natives are invisible to lookup.

Actions need the item to be connected

Every action resolves through find(). A remembered-but-disconnected hidden id cannot be activated, scrolled, launched, or menu-opened — false is returned.

onlyMenu items cannot be activated

hasActivate is false when the native item reports onlyMenu, even when a native activate function exists. Such items are menu-only by protocol; use openMenu().

Menus need hasMenu

openMenu() rejects items without a native menu:

The service does not synthesize a fallback menu for menuless icons.

Only one menu at a time

openMenu() calls closeMenu() first. Opening a second item's menu closes the first (emitting menuClosed for it) before attempting the new one.

closeMenu() is void

Unlike the boolean actions, closeMenu() (QML and IPC) returns nothing. Whether a menu was open is observable through menuClosed(id) and isMenuOpen, not a return value.

Scroll arguments are coerced, not validated

passes Number(delta) and Boolean(horizontal) straight to the native call. Non-numeric deltas become NaN at the native layer; the service does not range-check scroll steps.

Category mapping is lossy

Native categories collapse to four strings:

The raw numeric category is not exposed.

This section is for developers working on SystemTray.qml and the services/components that consume it.

6.1 Overall architecture

The service is a reactive adapter over the native tray model with a small Config-backed visibility layer and a service-owned menu:

6.2 Configuration structure

_hiddenIds is the normalized in-memory copy (stringified, deduplicated, blanks dropped). _configSection is the last-seen full systemTray object so writes preserve unknown keys.

Everything else (connected items, statuses, menus) is live native state, not stored configuration.

6.3 Adapter creation

The Instantiator mirrors the native model one-to-one:

Adapters are lightweight Items (invisible, zero-size) exposing derived state. Native property watchers (Connections on adapter._nativeItem) translate native changes into itemChanged(id) plus attention refreshes and menu invalidation:

onObjectAdded schedules a sync and emits itemAdded(id); onObjectRemoved closes the active menu when needed, schedules a sync, and emits itemRemoved(id).

6.4 Model synchronization

_syncModels() is the only place the four public arrays are replaced:

All callers except refresh IPC go through _scheduleModelSync():

Rapid bursts (several native adds, a config sync, an id change) therefore collapse into one rebuild. refresh IPC bypasses the flag and calls _syncModels() synchronously — useful when a test or script needs the arrays to reflect the instantiator now rather than on the next event-loop turn.

6.5 Visibility write path

Identical writes are short-circuited before touching Config, so re-pinning an already-pinned id is a cheap true.

6.6 Lookup and capability checks

find(id) linearly scans _items for an exact item.id === String(id) match. Empty ids return null immediately.

Actions resolve through find() and then capability-gate:

secondaryActivate() and scroll() mirror this with their own capabilities. launch() inserts a desktop-entry attempt before the activation fallback.

6.9 Config reactivity

syncFromConfig() normalizes and JSON-compares before mutating, so unrelated config edits (another section changing revision) do not churn the tray.

6.10 IPC architecture

IPC is a thin external interface over the same service functions:

Listings (list/pinned/hidden/attention/get) return JSON.stringify()-ed _snapshot() data; get returns "" for unknown ids. Boolean actions return the same bool the QML function returns. closeMenu/refresh are void.
